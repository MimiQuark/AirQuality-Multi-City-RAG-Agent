# RAG 检索与拒答评测报告

> 本报告记录 2026-10 对 RAG 模块的一次系统性评测整改。
> 所有数字均由 `backend/evaluation/eval_rag.py` 实测产生，复现命令见文末。

---

## 0. 结论摘要

整改前，RAG 的三项指标（Recall@1 / Recall@5 / 拒答准确率）**全部是 1.000**。
排查后发现这组满分**不是能力，而是评测集与方法本身的问题**：三处缺陷叠加，
使指标失去了区分度。整改后指标下降到真实水平，但**每一项都能追溯到具体样本**。

| 项目 | 整改前 | 整改后（BGE 语义模型） |
|---|---|---|
| 检索集 | 110 条，100% 题面照抄文档标题 | 66 条口语化提问，0% 含标题 |
| 拒答集 | 44 条，**全部**为"应拒答"，无正样本 | 48 条平衡集（24 应拒 / 24 应答） |
| Recall@1 | 1.000（**评测集同义反复，无意义**） | **0.818** |
| Recall@5 | 1.000 | **0.955** |
| MRR | 1.000 | **0.870** |
| 拒答准确率 | 1.000（**"永远拒答"即可满分**） | **0.958**（应拒 0.958 / 应答 0.958） |

---

## 1. 发现一：原检索集是"同义反复"，满分是必然的

`rag_cases.json` 的 110 条检索样本，实际只对应 **11 篇知识库文档**——
每篇文档配了 10 条**几乎同义的改写**：

```
rag-0 | HJ 633-2012 环境空气质量指数(AQI)技术规定        -> hj633-1
rag-1 | 请解释HJ 633-2012 环境空气质量指数(AQI)技术规定   -> hj633-1
rag-2 | HJ 633-2012 环境空气质量指数(AQI)技术规定的详细规定是什么 -> hj633-1
```

而 `service.py` 的打分公式里，**标题精确匹配占 0.60 权重**：

```python
rerank_score = 0.60 * title_score + 0.25 * keyword + 0.15 * vector + fused
```

题面里原样包含文档标题 ⇒ `title_score = 1.0` ⇒ 直接拿满 0.60 分并锁定答案。

实测统计：**v1 集中 100% 的题面都包含目标文档标题原文**，v2 困难集中为 0%。

> 因此 `Recall@1 = 1.000` 衡量的是"题面是否照抄了标题"，不是检索质量。
> 这组数字对 hash-v1 和 BGE 完全一样——**换模型指标不动，说明评测没有区分度**。

---

## 2. 发现二：重排权重被这套评测集带偏，反而拖累真实检索

在困难集（v2，口语化提问）上做权重消融，Recall@1：

| 打分方案 | hash-v1 (v1) | hash-v1 (v2) | BGE (v1) | BGE (v2) |
|---|---:|---:|---:|---:|
| **原公式** 标题0.60 / 词0.25 / 向量0.15 | 1.000 | *0.470* | 1.000 | *0.500* |
| 去标题，词0.50 / 向量0.30 / RRF | 0.291 | 0.576 | 0.945 | 0.773 |
| 纯 RRF 融合 | 0.373 | 0.636 | 0.564 | 0.742 |
| 纯向量余弦 | 0.291 | 0.515 | 0.936 | 0.803 |
| **新标定** 向量0.70 / 词0.10 / 标题0.10 / RRF0.02 | 0.882 | **0.561** | 1.000 | **0.818** |

**结论**：原公式把语义信号压到 0.15，在真实口语化提问上让 BGE 损失约 **30 个百分点**
（0.500 → 0.818）。它是在"题面照抄标题"的 v1 上调出来的，属于过拟合评测集。

新权重由网格搜索得到，同时满足"v1 不退化（1.000）+ v2 显著提升（0.818）"。

---

## 3. 发现三：逐条过滤是死代码，且该机制本身无收益

原实现：

```python
if fused < self.min_score / 100:   # min_score=0.15 → 阈值 0.0015
    continue
```

RRF 取值量级约 `1/60 ≈ 0.0167`，第 110 名也有 0.009，**恒大于 0.0015**——
这行过滤永远不生效。同时它把量级 0.0167 的 RRF 与 0-1 的分项相加，混合分尺度本身也不自洽。

整改时先修成"相对下限"（保留 `cos ≥ min_score × 最高分` 的分块），再做参数扫描：

| min_score | hash v1 | hash v2 | BGE v1 | BGE v2 |
|---:|---:|---:|---:|---:|
| **0.00（关闭）** | **1.000** | **0.894** | **1.000** | **0.955** |
| 0.30 | 0.864 | 0.833 | 1.000 | 0.955 |
| 0.50 | 0.664 | 0.697 | 1.000 | 0.955 |
| 0.80 | 0.455 | 0.576 | 1.000 | 0.970 |

**结论**：该机制对语义模型几乎无收益（0.955→0.955），却把稀疏哈希模型从 1.000 打到 0.345。
数据不支持它，因此**默认关闭**（`min_score=0`），并保留为可调参数。
真正的闸门改由拒答置信度承担——这道闸门是经过标定的。

## 4. 发现四：所谓"低置信度拒答"，实际是硬编码关键词白名单

原实现：

```python
domain_terms = ("空气质量", "AQI", "IAQI", "PM2.5", ..., "预警", "标准", "限值")
has_evidence = bool(strongest and has_domain_term)   # ← 只看问题里有没有这些词
refused = not has_evidence
```

拒答判定与检索分数**完全无关**，而是查用户提问里有没有出现预设词。后果：

* 新拒答集（24 条超纲 + 24 条领域内口语化提问，共 48 条）上，**准确率仅 0.562**；
* **24 条领域内问题里有 18 条被错误拒答**，例如：

```
夏天下午在户外跑步会不会伤肺     ← 会拒答，但库里 health-2 有答案
刮沙尘的时候怎么防护             ← 会拒答，但库里 health-3 有答案
北方冬天为什么空气差             ← 会拒答，但库里 season-1 有答案
```

原"拒答准确率 1.000"的来源也随之明确：原 44 条样本**全部**是"应拒答"的负样本，
**没有一条正样本**——"永远拒答"即可满分。

## 5. 整改：拒答改为基于检索置信度的阈值

置信度取**全库最高余弦相似度**（不用转换后的混合分：`(cos+1)/2` 会把无关文本的
底噪抬到 0.5-0.6，阈值失去可解释性）。

标定方法：48 条平衡集按分层方式拆成 24 训练 / 24 留出，在训练集上扫描阈值：

| 阈值 (cos) | 全集准确率 | 误拒率（该答却拒） | 漏拒率（该拒却答） |
|---:|---:|---:|---:|
| 0.457 | 0.917 | 0.042 | 0.125 |
| **0.467** | **0.958** | 0.042 | 0.042 |
| 0.475 | 0.958 | 0.042 | 0.042 |
| 0.495 | 0.958 | 0.083 | 0.000 |
| 0.504 | 0.917 | 0.167 | 0.000 |

* 训练集最优阈值 `0.475`，**留出集准确率 0.917**
* 取整为 `0.47` 作为 BGE 默认值，全集准确率 0.958

### 5.1 离线 hash provider 无法承担语义拒答（已实测确认）

对 hash-v1 分别用"原始余弦"和"混合分"两种信号扫描，**都不存在可行阈值**：

| provider / 信号 | 应拒样本均值 | 应答样本均值 | 可行区间 |
|---|---:|---:|---|
| hash-v1 / 余弦 | 0.171 | 0.226 | **无**（锚点冲突） |
| hash-v1 / 混合分 | 0.498 | 0.553 | **无**（锚点冲突） |
| BGE / 余弦 | 0.394 | 0.577 | (0.409, 0.537) ✔ |
| BGE / 混合分 | 0.584 | 0.677 | (0.576, 0.658) ✔ |

锚点冲突的具体表现：必须拒答的"建筑抗震设计规范怎么规定"得分 0.317，
而必须应答的"雾霾天老人能出门吗"只有 0.152——**排序是反的**。

因此：

* 离线 hash 的拒答阈值只能取保守值（0.12，保证领域内问题不被误拒），
  其拒答指标**仅供参考**；
* **CI 护栏对离线 provider 只设检索指标，不设拒答指标**（对做不了的指标设护栏没有意义）；
* 需要在 CI 上守拒答质量时，装好 `sentence-transformers` 后设 `USE_REAL_EMBEDDINGS=1` 再跑。

## 6. 整改前后对比（最终指标）

评测命令：`python -m backend.evaluation.eval_rag --all`

| 评测集 / provider | Recall@1 | Recall@5 | MRR | 拒答准确率 | 应拒 | 应答 |
|---|---:|---:|---:|---:|---:|---:|
| v1 简单集 / hash-v1 | 0.882 | 1.000 | 0.927 | 0.045 | 0.045 | n/a |
| v1 简单集 / BGE | 1.000 | 1.000 | 1.000 | 0.886 | 0.886 | n/a |
| **v2 困难集 / hash-v1** | 0.561 | 0.894 | 0.679 | 0.542 | 0.125 | 0.958 |
| **v2 困难集 / BGE** | **0.818** | **0.955** | **0.870** | **0.958** | 0.958 | 0.958 |

**同一套困难集上，BGE 相对离线哈希：Recall@1 +25.7 点，MRR +19.1 点。**
这是第一个能真正体现语义检索价值的指标。

## 7. 诚实边界

1. **知识库只有 11 篇文档**，检索本质是 11 路分类，绝对指标偏高，不能外推到生产规模。
2. **v2 拒答集 48 条为自建样本**，阈值在其上标定；样本量小，留出集仅 24 条，
   置信区间宽。扩样后需要重新标定。
3. **端到端回答质量未评测**：本报告只覆盖检索与拒答，未覆盖 LLM 生成环节的
   事实性与幻觉率。
4. **离线 hash 的检索指标偏低是设计使然**（词面哈希 + 重排公式），
   它只用于 CI 回归，不代表线上表现。

## 8. 复现方式

```bash
# 离线（无需模型，CI 路径）
python -m backend.evaluation.eval_rag

# 语义模型：两套评测集 x 两种 embedding 对比表 + 阈值扫描
pip install -e ".[rag]"
set USE_REAL_EMBEDDINGS=1      # PowerShell: $env:USE_REAL_EMBEDDINGS="1"
python -m backend.evaluation.eval_rag --all --sweep

# 全量质量流水线
python scripts/record_checks.py
```

产物：`reports/rag_eval/{latest.json, ablation.json, threshold_sweep.json, summary.md}`
